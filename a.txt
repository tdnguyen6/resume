Healing in the Cloud: Optimising Performance for Digital Health Apps
Project Overview

Digital health applications, such as remote patient monitoring, diagnostic AI tools, and telehealth platforms, increasingly rely on cloud computing for scalability and accessibility. However, these applications often suffer from inconsistent performance due to network latency, unpredictable server loads, and resource provisioning delays—especially during peak demand or in time-critical healthcare settings. This project will explore how cloud performance variability affects digital health services and develop methods to improve responsiveness, stability, and reliability for better patient outcomes.

Aims

The aim is to identify and address cloud performance issues that impact the reliability and speed of digital healthcare applications, ensuring they can meet the demands of modern clinical environments.

Objectives

Benchmark digital health app performance under varying cloud conditions (e.g., region, load, instance type).
Analyze key bottlenecks in latency, data throughput, and system responsiveness.
Explore different deployment strategies (e.g., autoscaling, edge offloading, multi-region redundancy).
Develop recommendations and automated tuning methods to optimize performance.
Validate the impact of optimizations using realistic healthcare workload simulations.
Significance

As digital health technologies become central to modern healthcare delivery, ensuring the speed and reliability of cloud-based systems is critical. Performance slowdowns or unpredictable delays can disrupt diagnoses, delay treatment, or erode trust in digital platforms—especially in scenarios where time is crucial. By identifying and addressing the root causes of cloud performance variability, this project will help make digital health applications more dependable and responsive. The outcomes will support the safe and effective use of cloud infrastructure in delivering timely, patient-centered care at scale.

One of my most recent work was to optimize a cloud-native application for up to a million users at a time. This includes identify and fix performance bottlenecks as well as perform large-scale load testing to verify the optimizations. Even worse, the system was very CPU-intensive and can barely support a hundred concurrent users without using a reasonable amount of cloud instances, that led to crashes in critical-time spikes (marketing campaigns). My first hypothesis was that it could be better with a CPU-optimized instance. However, my experiments quickly reject this even with the fastest CPU on the cloud. Finally, we needed to implement a custom caching solution which can be simply described as letting only the first worker performs the CPU-intensive work while others wait for the result. This greatly boosted the performance and the system has been stable which much less cloud resources than we anticipated. Another big challenge for me was to find a large scale load-testing method because no single machine can handle a million out-going connection at a time. This led me to develop a distributed load-testing script that run multiple parallel workers on AWS, each does a subset of the load and combine the results eventually as aggregate metrics.
